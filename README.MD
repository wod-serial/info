# README
В данном репозитории содержится публичная информация о ресурсах проекта "сериал" и инструкции по его восстановлению, если что-от пошло не так.

Явки и пароли, необходимые для данных задач, находятся у Джехи и у Кузьмина. Данный репозиторий является публичным, поэтому в нём никаких секретов не будет.

# Перенос

Тревога, тревога, волк унёс зайчат! Что делать, если нужно срочно всё спасать.

## Где оно находится сейчас

На яндекс облаке, на аккаунте Джехи. В дальнейших инструкциях будем исходить из худшего случая и того, что доступа к аккаунту нет, и надо быстро всё уносить.

## Требуемые мощности

На текущий момнет используется такая конфигурация:

* Платформа Intel Ice Lake
* Гарантированная доля vCPU 50%
​* vCPU 4
* RAM 4 ГБ
* Объём дискового пространства 120 ГБ

Для того, чтобы все ресурсы корректно и комфортно работали, нужно иметь не меньше RAM, чем указано выше.

## Требования к площадке

Любой хостинг, предоставляющий Linux машину и возможность разворачивать на ней докер контейнеры. Рекомендуется последняя версия дистрибутива Ubuntu, но в целом - без разницы, т.к. все ресурсы контейнеризированны.Можно хоть на личном ноуте на Win поднять.

## Требования к тому, кто всё спасёт

Никакого рокет сайнса нет, но если вы найдёте разработчика или devops, то он всё сделает очень быстро.

## Архитектура

Все ресурсы состоят из основных следующих контейнеров:
* mysql - база данных
* php - php нужной версии со всеми необходимыми расширениями
* nginx - nginx и кастомные для данного проекта настройки (рерайты).

Сверху на железной машине стоит nginx, который просто содержит все сертификаты и в зависимости от хоста проксирует запросы в nginx на нужных контейнерах.

Так же в docker compose есть примерно такой набор контейнеров:

```yaml
volumes:
  home: # файлы проекта
  images: # картинки
  mysql: # данные СУБД MySQL
  nginx-config: # конфиги nginx
  php-config: # конфиги php
```

Внимание! Несмотря на то, что везде используется MySQL и PHP - не стоит пытаться слить их воедино. Разным проектам требуются разные версии php и mysql с разными настройками. Биллинг, например, умеет работать только на устаревшей версии PHP. В теории можно это обновить и слить - но это долгая, нудная и совершенно бесполезная работа.

## Как развернуть копию

1. Получаем у Кузьмина ключ для захода по SSH
2. Подключаться надо командой `ssh -i путь_к_файлу kuzmin@wod-serial.jehy.ru`
3. После этого можно сделать `sudo su` - и вот ты админ
4. Останавливаем все контейнеры во избежание потери данных и коррапта СУБД. Можно сделать через консоль, можно сделать через UI управления контейнерами (явки и пароли у Кузьмина)
5. Архивируем содержимое `/etc/nginx`, `/var/www/html` и `/var/lib/docker/volumes` - больше вам ничего не нужно. Например, командой tar.
6. Копируем это на свой сервер. Например, подключившись к нему из текущего через rsync или mc.
7. Раскладываем данные в те же папки, что были на исходном сервере, чтобы их подхватил nginx и docker.
8. Ставим инструмент для управления контейнерами [по инструкции](https://docs.portainer.io/start/install-ce/server/docker/linux).
9. Заходим в нём в `Stacks` и стартуем все контейнеры, образы для них должны подтянуться при первом развёртывании.
10. Перенастраиваем домены, чтобы они смотрели на IP нового сервера. Берём явки и пароли у Кузьмина, домены принадлежат разным людям и находятся у разных регистраторов.
11. Настраиваем certbot для подключения SSL сертификатов (по инструкции в интернете, тысячи их)
12. Вы восхитительны
