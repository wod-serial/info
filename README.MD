# README

В данном репозитории содержится публичная информация о ресурсах проекта "сериал" и инструкции по его восстановлению, если что-от пошло не так.

Явки и пароли, необходимые для данных задач, находятся у Джехи и у Кузьмина. Данный репозиторий является публичным, поэтому в нём никаких секретов не будет.

# Перенос

Тревога, тревога, волк унёс зайчат! Что делать, если нужно срочно всё спасать.

## Где оно находится сейчас

На яндекс облаке, на аккаунте Джехи. В дальнейших инструкциях будем исходить из худшего случая и того, что доступа к аккаунту нет, и надо быстро всё уносить.

## Требуемые мощности

На текущий момнет используется такая конфигурация:

* Платформа Intel Ice Lake
* Гарантированная доля vCPU 50%
* vCPU 4
* RAM 4 ГБ
* Объём дискового пространства 120 ГБ

Для того, чтобы все ресурсы корректно и комфортно работали, нужно иметь не меньше RAM, чем указано выше.

## Требования к площадке

Любой хостинг, предоставляющий Linux машину и возможность разворачивать на ней докер контейнеры. 

Например, Yandex Cloud.

## Требования к ОС

Рекомендуется последняя версия дистрибутива Ubuntu, но в целом - без разницы, т.к. все ресурсы контейнеризированны. Можно хоть на личном ноуте на Win поднять.

## Требования к тому, кто всё спасёт

Никакого рокет сайнса нет, но если вы найдёте разработчика или devops, то он всё сделает очень быстро.

## Архитектура

Все ресурсы состоят из основных следующих контейнеров:
* `mysql` - база данных
* `php` - php нужной версии со всеми необходимыми расширениями
* `nginx` - nginx и кастомные для данного проекта настройки (обычно рерайты).

Сверху на железной машине стоит angie, который просто содержит все сертификаты и в зависимости от хоста проксирует запросы в nginx на нужных контейнерах.

Так же в docker compose каждого ресурса есть примерно такой набор томов для контейнеров:

```yaml
volumes:
  home: # php файлы проекта
  images: # картинки (в случае wiki)
  mysql: # данные СУБД MySQL
  nginx-config: # конфиги nginx
  php-config: # конфиги php
```

Внимание! Несмотря на то, что везде используется MySQL и PHP - не стоит пытаться слить их воедино. Разным проектам требуются разные версии php и mysql с разными настройками. Биллинг, например, умеет работать только на устаревшей версии PHP. В теории можно это обновить и слить - но это долгая, нудная и совершенно бесполезная работа.

## Как развернуть копию

1. Получаем у Кузьмина ключ для захода по SSH
2. Подключаться надо командой `ssh -i путь_к_файлу kuzmin@wod-serial.jehy.ru`
3. После этого можно сделать `sudo su` - и вот ты админ
4. Останавливаем все контейнеры во избежание потери данных и коррапта СУБД. Можно сделать через консоль, можно сделать через UI управления контейнерами (явки и пароли у Кузьмина)
5. Архивируем содержимое `/etc/angie`, `/var/www/html` и `/var/lib/docker/volumes` - больше вам ничего не нужно. Например, командой tar.
6. Копируем это на свой сервер. Например, подключившись к нему из текущего через rsync или mc.
7. Раскладываем данные в те же папки, что были на исходном сервере, чтобы их подхватил angie и docker.
8. Ставим инструмент для управления контейнерами [по инструкции](https://docs.portainer.io/start/install-ce/server/docker/linux).
9. Заходим в нём в `Stacks` и стартуем все контейнеры, образы для них должны подтянуться при первом развёртывании.
10. Перенастраиваем домены, чтобы они смотрели на IP нового сервера. Берём явки и пароли у Кузьмина, домены принадлежат разным людям и находятся у разных регистраторов.
11. Вы восхитительны!


# Полезное

## Про ресурсы

* Про вики есть отдельный док - [здесь](./WIKI.MD).
* Биллинг написан руками без фреймворка и на устаревшей версии PHP.
* Сайт `https://serial-wod.ru/` написан на фреймворке Yii.
* На этом же сервере поднят дайс бот Клэр, информация о нём - в [соседнем репозитории](https://github.com/wod-serial/ClairDiceBot).
* В директории `/var/www/html` лежит статический сайт https://season-food.serial-wod.ru/ - для ничего не нужно кроме настроек nginx из `/etc/nginx/sites-available/serial-season-food.conf`.
* Вебсайт и биллинг так же лежат на гитхабе [в приватных репозиториях wod-serial](https://github.com/wod-serial).

## Другие бекапы
* В яндекс облаке настроены снепшоты ВМ, из которых можно поднять бекап, если есть доступ.
* База данных биллинга и вебсайта так же резервируются через контейнеры `fradelg/mysql-cron-backup`, запущенные в их стеках. Бекапы лежат на ФС в виде SQL файлов.
* Бекап docker compose стеков делается отдельным контейнером `portainer-backup`, и лежит в `/var/lib/docker/volumes/portainer-backup_backup/_data` . Так же он лежит в отдельном репозитории этой же организации (https://github.com/wod-serial/docker-compose).


## Всякое
* В качестве удобных инструментов для работы с докер контейнерами, рекомендуется portainer, dozzle, glances, monocker.
* В некоторых стеках docker-compose так же есть контейнеры sftp и phpmyadmin - они сделаны для лёгкого доступа разработчиков сериала к нужным им ресурсам.
* Есть [Облачный мониторинг аптайма](https://wod-serial.betteruptime.com/).
* Для мониторинга состояния сервера используется zabbix agent.
* Почта настроена через [yandex postbox](https://yandex.cloud/ru/docs/postbox/quickstart#smtp-send). В случае переноса можно так же использовать, например, [smtp2go](https://www.smtp2go.com/).
* Часть контейнеров с веб интерфейсами для удобного администрирования (glances, dozzle) защищена через reverse proxy authentik. Они опциональны, и если эти слова вам незнакомы - просто не переносите это.
* На уровне сервера вместо nginx стоит angie. Это совместимый форк nginx. При переносе можно поставить его, чтобы перенести as is все конфиги и не утруждаться с SSL сертификатами. Понадобится доставить модули : `apt install angie-module-brotli angie-console-light angie-module-modsecurity`. Или можно поставить nginx, если с ним вам проще, и убрать параметры, которые ему незнакомы.
* Так же на сервере стоит modsecurity в режиме логирования (в самой OS) и crodwsec в режиме  защиты (в докере плюс фаервол-баунсер в системе). Это нужно, чтобы меньше ботов пыталсь сломать ресурсы. Поднимать их опционально. Баунсер ставится командой `apt install crowdsec-firewall-bouncer-iptables` - в целом мануалов по crowdsec много.
